# ビルド〜デプロイ手順書

対象読者：本プロジェクトのビルド・デプロイ作業を初めて行う担当者
前提：`npm install` 済みであること（未実施の場合は先に実行してください）

---

## 0. 全体の流れ

```
① 事前準備（初回のみ）
   ├─ clasp へのログイン
   ├─ Apps Scriptプロジェクトの用意と .clasp.json の作成
   └─ 問題マスタ／受験結果用スプレッドシートの用意とスクリプトプロパティ登録
        ↓
② ビルド＆コードのアップロード（コード変更のたびに実施）
   npm run push
        ↓
③ Webアプリとしてのデプロイ更新（公開URLに反映させたいときに実施）
   Apps Scriptエディタで「新バージョン」をデプロイ
```

`npm run push` は **コードをApps Scriptプロジェクトへアップロードするだけ** で、公開中のWebアプリURLには自動反映されません。URLに反映させるには③の手順が別途必要です。

---

## 1. 事前準備（初回のみ）

### 1-1. clasp へのログイン

```bash
npx clasp login
```

ブラウザが開くので、デプロイに使用するGoogleアカウントでログイン・許可してください。一度ログインすればPC内に認証情報が保存され、以降は不要です。

### 1-2. Apps Scriptプロジェクトの用意

まだ対象のApps Scriptプロジェクトが無い場合は、新規に作成します。

1. [script.google.com](https://script.google.com) を開く
2. 「新しいプロジェクト」を作成（スタンドアロンスクリプトでよい。特定のスプレッドシートに紐付ける必要はない）
3. プロジェクト名を分かりやすいものに変更（例：「プログラミングスキル判定テスト」）
4. アドレスバーのURL（`https://script.google.com/.../projects/【この部分】/edit`）から **スクリプトID** を控える

既存プロジェクトに対して作業する場合は、そのプロジェクトのスクリプトIDを担当者から共有してもらってください。

### 1-3. `.clasp.json` の作成

`.clasp.json` は `scriptId` を含み、GitHubにはコミットしない運用のため、各自のローカル環境で作成する必要があります。

リポジトリ直下の `.clasp.json.example` をコピーして `.clasp.json` を作成し、`scriptId` を1-2で控えた値に書き換えてください。

```bash
cp .clasp.json.example .clasp.json
```

```json
// .clasp.json（編集後の例）
{
  "scriptId": "ここに1-2で控えたスクリプトIDを貼り付ける",
  "rootDir": "dist"
}
```

`rootDir` は `"dist"` から変更しないでください（ビルド成果物の出力先と一致させる必要があります）。

### 1-4. 問題マスタ／受験結果用スプレッドシートの用意

1. 新規にGoogleスプレッドシートを作成する（1-2のApps Scriptプロジェクトとは別ファイルでよい。むしろ紐付けない）
2. シート（タブ）を2つ用意し、**名前を厳密に一致させる**
   - `問題マスタ`
   - `受験結果`
3. 「問題マスタ」シートの列構成は、`specification/JE-TechnicalSkillTester-spec.md` の7-1章（A:問題ID 〜 L:備考）に従って準備する
4. 「受験結果」シートは1行目にヘッダーを用意しておく（記録は`submitResult`実行時にA〜M列へ自動追記される。列構成は同spec 11-2章を参照）
5. スプレッドシートのURL（`https://docs.google.com/spreadsheets/d/【この部分】/edit`）から **スプレッドシートID** を控える

### 1-5. スクリプトプロパティへのスプレッドシートID登録

スプレッドシートIDはソースコードにハードコードせず、Apps Script側の「スクリプト プロパティ」に保持する。

1. Apps Scriptエディタを開く
   ```bash
   npm run open-script
   ```
2. 左メニューの「プロジェクトの設定」（歯車アイコン）を開く
3. 「スクリプト プロパティ」→「スクリプト プロパティを追加」
4. 以下のとおり登録して保存する

   | プロパティ | 値 |
   |---|---|
   | `SPREADSHEET_ID` | 1-4で控えたスプレッドシートID |

この登録は当該Apps Scriptプロジェクトに対して一度行えば、以降のビルド・デプロイのたびに再設定する必要はない。

## 2. ビルド＆コードのアップロード

コードに変更を加えるたびに、以下を実行する。

```bash
npm run push
```

`package.json` の定義上、これは次を順に実行する（`npm run build` の内容を含む）。

| 実行順 | スクリプト | 内容 |
|---|---|---|
| 1 | `lint` | ESLintによる静的検証（自動修正含む） |
| 2 | `test` | Vitestによる単体テスト実行 |
| 3 | `clean` | `dist/` を削除 |
| 4 | `bundle` | Rollupでサーバー側・クライアント側スクリプトをビルド |
| 5 | `copy-appsscript` | `src/appsscript.json` を `dist/` へコピー |
| 6 | `copy-views` | `src/client/views/**/*.html` を `dist/client/views/` へコピー |
| 7 | `inline-client-script` | クライアントバンドルを `script.html` の`<script>`へ埋め込み |
| 8 | `clasp push` | `dist/` の内容をApps Scriptプロジェクトへアップロード |

途中の `lint` や `test` でエラーが出た場合、そこで処理は止まり `clasp push` まで到達しない。エラー内容を確認し、修正してから再実行すること。

ビルドのみ行い `clasp push` は行いたくない場合は、代わりに以下を使う。

```bash
npm run build
```

## 3. Webアプリとしてのデプロイ更新

`npm run push` はコードをアップロードするだけであり、既存の公開URLの内容を更新するには、Apps Scriptエディタ上で明示的に「新バージョンのデプロイ」を行う必要がある。

### 3-1. 初回デプロイ

1. `npm run open-script` でエディタを開く
2. 右上の「デプロイ」→「新しいデプロイ」
3. 種類の選択（歯車アイコン）で「ウェブアプリ」を選択
4. 以下のとおり設定する（`src/appsscript.json` の`webapp`設定と合わせる）
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**（入社希望者など組織外のユーザーもアクセスするため。仕様書3-4章参照）
5. 「デプロイ」をクリックすると、Webアプリの `exec` URLが発行される

### 3-2. 2回目以降（コード更新をURLへ反映する場合）

1. `npm run open-script` でエディタを開く
2. 右上の「デプロイ」→「デプロイを管理」
3. 対象デプロイの鉛筆（編集）アイコンをクリック
4. 「バージョン」で「新バージョン」を選択
5. 「デプロイ」をクリック

同じURLのまま、中身だけ最新のコードに更新される。

### 3-3. 受験者への配布URL

発行された `exec` URLに、受験者区分に応じたクエリパラメータ `role` を付与して案内する（仕様書4-1章）。

| 区分 | URL例 |
|---|---|
| 入社希望者 | `https://script.google.com/macros/s/【デプロイID】/exec?role=applicant` |
| 未経験の新入社員 | `https://script.google.com/macros/s/【デプロイID】/exec?role=newhire` |
| 入社3年目までの社員 | `https://script.google.com/macros/s/【デプロイID】/exec?role=junior` |

## 4. その他のコマンド

| コマンド | 内容 |
|---|---|
| `npm test` | ビルド・デプロイを行わず、単体テストのみ実行 |
| `npm run build` | ビルドのみ（`clasp push` は行わない） |
| `npm run open-script` | Apps Scriptエディタをブラウザで開く |
| `npm run open` | 紐付いているコンテナ（ある場合）を開く |
| `npm run security-fix` | `npm audit fix` を実行 |

---

## 5. 注意事項

- `.clasp.json` は `scriptId` を含むためGit管理対象外（`.gitignore`済み）。担当者ごとに1章の手順でローカル作成すること。他人の `.clasp.json` をコピーして使い回さないこと（対象プロジェクトを取り違える事故防止のため、各自1-2から実施することを推奨）
- スプレッドシートIDは`SPREADSHEET_ID`スクリプトプロパティにのみ保持し、コードや `.env` 等のファイルに書かないこと
- `dist/` はビルド生成物であり、直接編集しないこと（`npm run build` のたびに削除・再生成される）
- 開発中に別のスプレッドシート（複製）で動作確認したい場合は、1-5の「スクリプト プロパティ」の値を一時的に差し替えるだけでよい（コード変更・再デプロイは不要）
