# プログラミングスキル判定テスト Webアプリケーション仕様書

- 版数：v2.0（Google Apps Script前提版）
- 対象読者：開発担当者、企画・人事担当者

---

## 1. 目的

IT業界未経験者〜入社3年目までの社員を対象に、プログラミング・SQL・ロジカルシンキング・行動指針に関する知識・考え方をWeb上で判定するテストを提供する。取得したデータを用いて、以下を実現する。

- 入社希望者に対する技量判断（採用選考の参考情報）
- 若手社員の苦手分野の把握と教育計画への反映

---

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| GAS | Google Apps Script。本システムのサーバーサイド処理・Webアプリ公開に使用する。 |
| 区分 | 出題テーマの大分類（コーディング／SQL／プログラミング技法／ロジカルシンキング／行動指針の5種）。 |

| 受験者 | 本テストを受ける人。「入社希望者」「未経験の新入社員」「入社3年目までの社員」の3区分がある。 |

## 3. システム構成（Google Apps Script前提）

### 3-1. 全体構成

本システムは、**Google Apps Script（GAS）** を実装基盤とすることを前提とする。

- **フロントエンド**：GASの `HtmlService` によって配信するHTML／CSS／JavaScript（受験画面・結果画面等）。
- **バックエンド**：GASのサーバーサイド関数（.gsファイル）。問題の抽出、採点、記録処理を担う。
- **データストア**：Googleスプレッドシート。最低限、以下2シートで構成する。
  1. 「問題マスタ」シート（出題データ、72問）
  2. 「受験結果」シート（受験者ごとの結果を1行ずつ蓄積）

```
                 ┌────────────────────────┐
受験者ブラウザ ───▶│ GAS Webアプリ (doGet)   │
                 │  ・role判定             │
                 │  ・HTML(HtmlService)配信 │
                 └───────────┬────────────┘
                             │ google.script.run
                 ┌───────────▼────────────┐
                 │ GASサーバーサイド関数     │
                 │ ・問題抽出 / 採点 / 記録  │
                 └───────────┬────────────┘
                             │ SpreadsheetApp
                 ┌───────────▼────────────┐
                 │ Googleスプレッドシート    │
                 │ ・問題マスタ シート       │
                 │ ・受験結果 シート         │
                 └────────────────────────┘
```

### 3-2. データソースとしてのGoogleスプレッドシート

- 問題バンク（72問以上）は、GASから参照するGoogleスプレッドシート「問題マスタ」シートに保持する（データ構造は7-1参照）。
- GASは `SpreadsheetApp.openById(SHEET_ID)` 等でスプレッドシートを取得し、シート内容を読み込んで出題データとして利用する。
- 問題の追加・修正・削除は、コードを変更せず「問題マスタ」シートの編集のみで行える構成とする。

### 3-3. 開発方法

- Typescriptでコードを作成し、RollupによりJavaScriptにトランスパイル、claspでデプロイする方式とする。

### 3-4. Webアプリとしての公開方法

- 本システムは、GASの「ウェブアプリとしてデプロイ」機能を用いて公開する。
- `doGet(e)` 関数がHTTPリクエストを受け付け、URLパラメータ（`role`）に応じて表示するHTMLを出し分ける（4-1参照）。

```javascript
// Code.gs（イメージ）
function doGet(e) {
  var role = e.parameter.role;
  var validRoles = ['applicant', 'newhire', 'junior'];

  if (validRoles.indexOf(role) === -1) {
    return HtmlService.createHtmlOutput(
      '<p>このページには、管理者から案内された専用URLからアクセスしてください。</p>'
    );
  }

  var template = HtmlService.createTemplateFromFile('Index');
  template.role = role;
  return template.evaluate()
    .setTitle('プログラミングスキル判定テスト')
    .addMetaTag('viewport', 'width=device-width, initial-scale=1');
}
```

- デプロイ設定について、入社希望者（組織外の人）もアクセスする想定であるため、「アクセスできるユーザー」は「全員」とする必要がある。
- この場合、スクリプトは「実行するユーザー＝デプロイした本人（またはデプロイ設定で指定したアカウント）」の権限で動作するため、スプレッドシートへの読み書き権限はそのアカウントに紐づく。デプロイ担当アカウントの管理（退職時の引き継ぎ等）に留意する。

## 4. 受験者区分と権限差異

### 4-1. 受験者区分の指定方法（URLパラメータ方式）

受験者区分は、受験者自身に選択させるのではなく、**管理者があらかじめ発行するURLのクエリパラメータによって指定する。**

| パラメータ名 | 値 | 対応する受験者区分 |
|---|---|---|
| `role` | `applicant` | 入社希望者 |
| `role` | `newhire` | 未経験の新入社員 |
| `role` | `junior` | 入社3年目までの社員 |

例（`XXXX` はGASのデプロイID）：

- 入社希望者向け：`https://script.google.com/macros/s/XXXX/exec?role=applicant`
- 未経験の新入社員向け：`https://script.google.com/macros/s/XXXX/exec?role=newhire`
- 入社3年目までの社員向け：`https://script.google.com/macros/s/XXXX/exec?role=junior`

**サーバーサイドでの検証（GASならではの利点）**

- `role` パラメータの検証は、`doGet(e)` 関数内、すなわち**サーバーサイド（GAS実行環境）** で行う（3-3のコード例参照）。
- 検証はブラウザにHTMLが届く前に行われるため、ブラウザの開発者ツールでクライアント側の変数を書き換えても、サーバー側の判定結果そのものを覆すことはできない。
- 判定の結果、`role` が不正・未指定の場合は、開始画面を含む本来のHTMLを一切返却せず、案内メッセージのみのHTMLを返す。

**限界事項（重要）**

- サーバーサイドで検証するとはいえ、`role` の値自体はURLというユーザーが自由に書き換えられる場所に置かれている。そのため、受験者がURLの `role` の値を別の区分の値に書き換えてアクセスすることは技術的に可能であり、なりすまし対策としては限定的である。
- 厳密な不正防止（本人以外が別区分のURLを推測・使い回しできないようにする）が必要な場合は、14章の拡張案にある「発行済みトークン方式」への拡張を検討すること。

### 4-2. 受験者区分ごとの権限差異

| 受験者区分 | 社員番号入力 | 所属入力 | 終了時の操作 | 正解率の表示 |
|---|---|---|---|---|
| 入社希望者 | 非表示 | 非表示 | 「回答終了」ボタン | 表示しない |
| 未経験の新入社員 | 表示 | 表示 | 「採点」ボタン | 表示する |
| 入社3年目までの社員 | 表示 | 表示 | 「採点」ボタン | 表示する |

- 「未経験の新入社員」と「入社3年目までの社員」は、画面上の挙動（項目表示・ボタン・結果表示）は同一とする。記録データ上の受験者区分としてのみ区別し、教育計画立案時の分析に用いる。

```

   │
   ▼

   │                              │
   │ 不正・未指定                  │ 正常（applicant/newhire/junior）
   ▼                              ▼
[アクセス方法エラー画面]        [開始画面]
（案内文のみ表示し、             │ 氏名等の入力・「テスト開始」
　テストには進めない）           ▼
                             [受験画面]（全30問）
                                │ 制限時間30分のカウントダウン表示

                       [入社希望者]              [社員]
```

### 5-1. 管理者による結果確認

- 受験結果はGoogleスプレッドシート「受験結果」シートに直接蓄積されるため、管理者はスプレッドシートを開くだけで、フィルタ・ソート・ピボットテーブルなどGoogleスプレッドシート標準機能を使って集計・分析できる。専用の管理画面（Web UI）を別途作り込む必要は必須ではない。
- 簡易な集計ビュー（区分別の平均正解率など）をWebアプリ内に用意したい場合は、`doGet(e)` に管理者向けの別パラメータ（例：`?admin=1`）を用意し、`Session.getActiveUser().getEmail()` で取得したアクセス者のメールアドレスが、あらかじめ定めた管理者リストに含まれる場合のみ集計結果を表示する、といった実装とする（本仕様ではオプション機能とする）。

## 6. 開始画面 仕様

### 6-1. 入力項目

受験者区分は、開始画面に到達する前の時点でURLパラメータ（4-1参照）によりサーバーサイドで確定している。そのため、開始画面には受験者区分を選択・変更するUIは設けず、確定済みの区分に応じて以下の項目の表示・非表示を自動的に切り替える。

| 項目名 | 入力形式 | 必須 | 表示条件 | 備考 |
|---|---|---|---|---|
| 氏名 | テキストボックス | 必須 | 常時表示 | 全角・半角どちらも許容。 |
| 社員番号 | テキストボックス | 必須 | URLパラメータの区分が「入社希望者」以外のとき表示 | 半角英数字を想定。 |
| 所属 | テキストボックス | 必須 | URLパラメータの区分が「入社希望者」以外のとき表示 | 全角・半角どちらも許容。 |

- 確定した受験者区分を「〇〇として受験します」等の形で画面上に表示し、受験者が誤ったURLを案内されていないか気づける状態にすることが望ましい。

### 6-2. 画面上の説明表示

- 出題数（全30問）、出題形式（選択式はチェックボックスから1つ選択、記述式はテキスト入力）、制限時間（30分）を開始前に受験者へ明示する。
- 「テスト開始」ボタン押下時に必須項目の入力チェックを行い、未入力があればエラーメッセージを表示して開始しない。

### 6-3. 開始時の処理

1. 受験者が「テスト開始」ボタンを押下すると、クライアントJavaScriptから `google.script.run.withSuccessHandler(...).getQuizQuestions(role)` を呼び出す。
2. サーバーサイド関数 `getQuizQuestions(role)` が「問題マスタ」シートを読み込み、出題ロジック（7章）に従い30問を抽出し、各問題の選択肢の表示順をシャッフルした上で、問題セット（JSON相当のオブジェクト）をクライアントに返却する。
3. クライアントは受け取った問題セットをもとに1問目を表示し、試験開始時刻を記録してタイマーを起動する（9章）。

## 7. 出題ロジック仕様

### 7-1. 問題マスタ（スプレッドシート）のデータ構造

「問題マスタ」シートは、1行につき1問を保持する。想定する列構成は以下の通り（1行目はヘッダー行）。

| 列 | 項目 | 内容 |
|---|---|---|
| A | 問題ID | 一意の識別子（例：`cod-if-01`）。受験結果シートとの突き合わせに使用。 |
| B | 区分 | 大区分名（コーディング／SQL／プログラミング技法／ロジカルシンキング／行動指針）。 |
| C | 小区分 | 小区分名（例：if文の条件式）。 |
| D | 出題形式 | `choice`（選択式）または `text`（記述式）。 |
| E | 問題文 | 出題文。 |
| F〜I | 選択肢1〜4 | 選択式の場合のみ使用。記述式の場合は空欄。 |
| J | 正解番号 | 選択式の場合のみ使用。選択肢1〜4のうち正解の列番号（1〜4）。 |
| K | 模範回答 | 記述式の場合のみ使用。 |
| L | 備考 | 出題意図等の補足（受験者には非表示、管理者・出題担当者向け）。 |

- GASは `getDataRange().getValues()` 等でシート全体を読み込み、各行を上記の構造に沿ったオブジェクトへ変換した上で7-2以降の抽出処理を行う。

### 7-2. 抽出単位

区分（大分類）ごとに6問ずつ、5区分合計30問を抽出する。

| 区分 | 問題マスタ内の問題数（本仕様策定時点） | 抽出数 |
|---|---|---|
| コーディング | 39問 | 6問 |
| SQL | 6問 | 6問（全問採用） |
| プログラミング技法 | 6問 | 6問（全問採用） |
| ロジカルシンキング | 6問 | 6問（全問採用） |
| 行動指針 | 15問 | 6問 |
| **合計** | **72問** | **30問** |

- 区分内の問題数が抽出数（6問）以下の場合は、その区分の全問を採用し、出題順のみランダムにする。
- 区分内の問題数が抽出数を超える場合（コーディング・行動指針）は、以下7-3の方法でランダム抽出する。

### 7-3. 記述式問題の配分（コーディング区分の例）

「記述式もまんべんなく入るように」という要件に対応するため、対象区分内の「選択式問題数」と「記述式問題数」の構成比に応じて、抽出数（6問）を按分する。

1. 対象区分内の記述式問題の比率を求める（記述式問題数 ÷ 区分内の全問題数）。
2. 抽出数6問にその比率を掛け、四捨五入して「記述式の抽出目標数」とする。ただし、区分内に記述式が1問以上存在する場合は目標数を最低1問とする。
3. 残りを「選択式の抽出目標数」とする。
4. 記述式・選択式それぞれのプールからランダムに目標数を抽出し、両者を合わせた上で出題順をランダムにする。

例：コーディング区分（全39問、うち記述式11問・選択式28問）の場合、記述式目標数は 6 ×(11/39) ≈ 1.7 → 2問、選択式は4問となる。

- 行動指針区分は問題マスタ内に記述式問題が存在しないため、6問すべて選択式から抽出する。
- 乱数の生成にはGASの `Math.random()` を用いる。

### 7-4. 出題順序

- 全30問は、区分ごとにまとめず、抽出後にシャッフルして出題する（区分名は受験者に開示しない）。
- 各問題には内部的に「区分」「小区分」を保持し、採点時の集計にのみ使用する。

## 8. 選択肢のランダム表示仕様

- 選択式問題の4つの選択肢は、`getQuizQuestions` 関数がサーバーサイドで返却する時点で、表示順をランダムに入れ替える（同一問題が別受験者・別回に出題された際、選択肢の並びが固定化しないようにするため）。
- シャッフル後も、各選択肢が「元のどの選択肢か（正解かどうか）」の対応情報は、サーバーサイドの一時データ（後述10章の採点処理用）または各選択肢に付与した正誤フラグとして保持し、選択された選択肢の表示位置ではなく、対応する正誤フラグに基づいて採点する。これにより、選択肢の順序を入れ替えても採点結果に誤りが生じないようにする。
- 1問につき正解は1つとする（複数正解問題は本仕様の対象外）。

## 9. 制限時間・経過時間表示仕様

### 9-1. 試験時間

- 制限時間は**30分**とする。
- 受験画面の表示開始時点（開始画面で「テスト開始」を押下し、`getQuizQuestions` の結果を受け取った時点）から計測を開始する。

### 9-2. 経過時間の表示

- 受験画面には、常時「経過時間」を表示する（例：`経過時間 12:34 / 制限時間 30:00`）。
- 表示形式は「分:秒」（mm:ss）とし、クライアント側JavaScriptの `setInterval` 等で1秒ごとに更新する。
- 残り時間が一定値（例：残り5分）を切った場合、表示色を変える等して受験者に視覚的な注意喚起を行う（詳細な閾値・配色は実装時に調整可）。

### 9-3. 時間切れ時の挙動

制限時間（30分）に達した時点で、クライアント側で以下を自動的に行う。

1. 全ての選択肢（チェックボックス）およびテキスト入力欄を操作不可（disabled）状態にする。すでに入力・選択済みの内容はそのまま保持する。
2. 問題間のページ送り（前へ／次へ、問題番号ジャンプ等）による回答内容の変更操作も無効化する。
3. 受験者区分に応じて、次のいずれかのボタンのみをクリック可能な状態にする。
   - 入社希望者：「回答終了」ボタン
   - 社員（未経験の新入社員／入社3年目までの社員）：「採点」ボタン
4. 時間切れになった旨を画面上に明示する（例：「制限時間に達しました。ここまでの回答内容で終了します。」等のメッセージ表示）。

### 9-4. 時間内終了時の挙動

- 制限時間内に受験者が自ら「採点」または「回答終了」ボタンを押した場合は、9-3の時間切れ処理と同様に以降の入力を無効化した上で、10章の採点処理・11章の記録処理に進む。
- 制限時間に達した場合でも、ボタン押下は受験者自身の操作を必要とし、自動的に採点・記録処理を行うことはしない（受験者が最終確認の上でボタンを押す運用とする）。

## 10. 採点仕様

### 10-1. 採点処理の実行場所

- 採点処理は、クライアント側JavaScriptではなく、**GASのサーバーサイド関数**（例：`submitResult(payload)`）で行う。
- 「採点」または「回答終了」ボタン押下時、クライアントは受験者の全回答（選択式の選択内容、記述式の入力内容）を `payload` としてサーバーサイド関数に送信する。
- サーバーサイド関数は、送信された回答と、問題マスタ（またはサーバー側で保持している出題時の正解情報）を突き合わせて正誤判定・採点を行い、その結果を受験結果シートに記録した上で、（社員区分の場合のみ画面表示するための）採点結果をクライアントに返却する。
- 採点をサーバーサイドで行うことで、クライアント側のJavaScriptやブラウザの通信内容を書き換えることによる不正な点数操作を防止する。

### 10-2. 採点対象

- **選択式問題のみを自動採点の対象とする。**
- 記述式問題は模範回答と受験者の回答内容をそのまま受験結果シートに記録し、自動での正誤判定は行わない（プログラムの記述内容は表記ゆれが大きく、単純な文字列比較では正確な採点ができないため）。記述式問題は後日、担当者が模範回答と照らして確認する運用とする。

### 10-3. 正解率の算出

| 項目 | 算出方法 |
|---|---|
| 総合正解率 | （選択式問題の正解数 ÷ 出題された選択式問題数）× 100 |
| 区分別正解率 | 区分ごとに（その区分内の選択式問題の正解数 ÷ その区分内の選択式問題数）× 100 |

- 記述式問題は正解率の分母・分子いずれにも含めない。
- 区分別正解率とあわせて、区分ごとの「記述式提出数」（提出済み／未提出）も参考情報として算出・記録する。

### 10-4. 結果表示（社員のみ）

サーバーサイドでの採点完了後、クライアントは受験者区分に応じて以下のように結果を扱う。

- 未経験の新入社員／入社3年目までの社員：サーバーから返却された採点結果（総合正解率、区分別正解率、各区分の出題数・正解数・記述式提出数）を画面表示する。
- 入社希望者：サーバー側では同様に採点・記録処理を行うが、クライアントは採点結果を画面に表示せず、結果を伏せたお礼・終了メッセージのみを表示する。

## 11. データ記録仕様（Googleスプレッドシートへの記録）

### 11-1. 記録タイミング

「採点」または「回答終了」ボタン押下時点（9-3・9-4の処理後）に、サーバーサイド関数 `submitResult(payload)` 内で、1回分の受験結果として「受験結果」シートに1行追記する。

### 11-2. 記録項目（「受験結果」シートの列構成）

| 列 | 項目 | 内容 |
|---|---|---|
| A | 記録日時 | `new Date()` 等、サーバー側の現在日時（テスト終了時点）。 |
| B | 受験者区分 | 入社希望者／未経験の新入社員／入社3年目までの社員。 |
| C | 氏名 | 開始画面での入力値。 |
| D | 社員番号 | 開始画面での入力値（入社希望者の場合は空欄）。 |
| E | 所属 | 開始画面での入力値（入社希望者の場合は空欄）。 |
| F | 総合正解率 | 10-3の算出結果（入社希望者にも記録する。画面表示のみ行わない）。 |
| G〜K | 区分別正解率（5区分分） | 区分ごとの正解率・出題数・正解数。 |
| L | 所要時間／時間切れフラグ | 開始から終了までの経過時間、または時間切れによる終了かどうか。 |
| M | 各設問の回答詳細 | 設問ID・区分・小区分・出題形式・回答内容・正誤（選択式）・模範回答（記述式）をJSON文字列等でまとめて格納する（1セルにまとめるか、別シート「回答詳細」に正規化して格納するかは実装時に選定）。 |

### 11-3. 同時書き込みに関する考慮

- 複数の受験者がほぼ同時に「採点」ボタンを押下した場合、スプレッドシートへの追記処理が競合する可能性がある。
- `LockService.getScriptLock()` を用いて、`appendRow` を含む一連の書き込み処理をロックし、同時実行による行の欠落・上書きを防止すること。

```javascript
function submitResult(payload) {
  var lock = LockService.getScriptLock();
  lock.waitLock(30000); // 最大30秒待機
  try {
    // 採点処理・SpreadsheetApp.appendRow 等
  } finally {
    lock.releaseLock();
  }
}
```

### 11-4. 管理者による参照

- 5-1のとおり、管理者は「受験結果」シートを直接開くことで、記録済みデータの一覧・集計・分析ができる。
- 個人情報（氏名・社員番号）を扱うため、当該スプレッドシートの共有設定は、人事・採用担当者等の必要な範囲に限定する。

## 12. 非機能要件

| 項目 | 要件 |
|---|---|
| 対応デバイス | PC・タブレット・スマートフォンのブラウザで問題なく操作できること（レスポンシブ対応）。 |
| ブラウザ | 主要ブラウザ（Chrome、Edge、Safari等）の最新版で動作すること。 |
| アクセシビリティ | チェックボックス・ボタン等はキーボード操作でも選択・押下できること。 |
| データ保護 | 氏名・社員番号などの個人情報を扱うため、Googleアカウントの権限管理・スプレッドシートの共有範囲設定を適切に行うこと。 |
| GAS実行時間制限 | 1回のスクリプト実行は、無料のGoogleアカウントで最大6分、Google Workspaceアカウントで最大30分に制限される。問題抽出・採点処理はこの時間内に確実に収まる設計とする。 |
| GAS同時実行・クォータ | 大量アクセス時のスプレッドシート同時書き込み（11-3のLockService対応）、および1日あたりのスクリプト実行回数等のクォータ上限に留意する。大規模運用（同時受験者数が多い、頻繁に実施する等）が見込まれる場合は、Google Workspaceの契約内容・上限緩和策を事前に確認すること。 |
| 可用性 | タイマー動作中にブラウザの再読み込み等が発生した場合の挙動（再開できるか、最初からになるか）を実装時に定義すること。 |

## 13. 前提条件・制約事項

- 本仕様は、**Google Apps ScriptおよびGoogleスプレッドシートを実装基盤とすること**を前提とする。
- 問題マスタの内容（72問）は別紙「プログラミングスキル判定テスト_問題集」を正とする。問題の追加・修正を行う場合は、7-1のシート列構成（区分・小区分・出題形式・正解番号等の対応関係）を崩さないよう管理すること。
- 選択肢のランダム表示・記述式の配分ロジック（7章・8章）は、出題プールの問題数・記述式比率が変化した場合、按分計算のロジックも見直しが必要となる。
- 受験者区分のURLパラメータ方式（4-1）は、サーバーサイドで検証を行うものの、URLの値自体を受験者が書き換えることによる区分の詐称を技術的に完全には防止できない。厳密な不正防止が必要な業務要件がある場合は、14章に記載のトークン方式等への拡張を検討すること。
- Webアプリのデプロイ設定（「実行するユーザー」「アクセスできるユーザー」）、およびスプレッドシートの共有範囲は、個人情報保護の観点から、開発・運用担当者が責任をもって設定・管理すること。

## 14. 今後の拡張案（参考）

- 受験者区分の詐称・URL使い回しを防ぐため、「区分＋受験者（または受験回）を一意に識別するトークン」を「発行済みトークン」シートで管理し、`doGet(e)` でトークンの有効性を検証した上でのみテストを開始できるようにする方式への拡張。一度使用したトークンは無効化する。
- 社内の受験者（未経験の新入社員／入社3年目までの社員）については、Google Workspaceアカウントでログイン済みであれば `Session.getActiveUser().getEmail()` を用いて氏名・所属を自動取得し、開始画面での入力を省略する仕組みの検討（入社希望者は組織外のためこの方式は適用できない）。
- 記述式問題について、簡易的な自動採点（キーワードマッチングなど）を補助的に導入し、担当者の確認負荷を軽減する仕組みの検討。
- 受験結果の推移をグラフ化し、同一受験者の複数回受験・成長度合いを可視化する機能（Googleスプレッドシートのグラフ機能、またはGASからGoogle データポータル／Looker Studio等への連携）。
- 管理者向けの簡易サマリー画面（5-1で触れた `?admin=1` 等）へのログイン認証・権限確認機能の追加。
